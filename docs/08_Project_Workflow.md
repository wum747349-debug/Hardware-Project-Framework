# 项目工作流程

## 1. 文档定位

本文是仓库标准执行流程，用于规定 AI/Codex 执行硬件项目任务时的阶段边界、允许输出和仓库维护依据。它偏规则和执行边界，不是面向用户的完整教程，也不是普通任务的默认上下文。

普通任务应先按 `docs/AI_Context_Guide.md` 读取最小必要上下文；只有需要判断完整流程、阶段边界、是否允许生成 BOM、是否允许画原理图、是否需要 datasheet，或维护流程文档时，才读取本文。

面向用户的流程学习、阶段复盘和任务布置说明放在 `prompts/硬件项目工作流程总结.md`。

## 2. 总原则

本仓库采用渐进式硬件设计流程。

资料收集不是独立的一次性前置阶段，而是随关键器件候选、datasheet 阅读、模块设计说明和 BOM 草稿逐步展开。关键安全边界以 `PROJECT_RULES.md` 和 `AGENTS.md` 为准；本文只记录流程顺序、阶段权限和必要例外。

## 4. 阶段说明

以下阶段说明只记录阶段目标、关键进入条件、关键退出条件和特殊风险。完整输入、输出和权限以阶段总览表为准。

### 阶段 1：需求定义

- 阶段目标：明确第一版做什么、不做什么，以及电源、接口、尺寸、成本和调试边界。
- 关键进入条件：已有项目想法、约束或需求草稿。
- 关键退出条件：`requirements.md` 能支撑后续模块拆分。
- 特殊风险或例外：不生成 BOM，不画正式原理图。

### 阶段 2：模块方案拆分

- 阶段目标：拆分功能模块，明确模块间电源、信号和风险边界。
- 关键进入条件：需求边界已基本明确。
- 关键退出条件：`block_diagram.md` 和 `design_notes.md` 能说明系统结构。
- 特殊风险或例外：不读取所有 datasheet，不把普通外围器件作为第一轮重点。

### 阶段 3：第一轮关键器件候选选型

- 阶段目标：识别影响架构和关键参数的器件类别，形成候选搜索方向。
- 关键进入条件：需求、模块边界和主要风险模块已明确。
- 关键退出条件：候选表包含比较维度、风险点和待核对项。
- 特殊风险或例外：只允许候选表，不生成最终 BOM；立创商城由用户手动搜索和下载资料。

### 阶段 4：关键 datasheet 阅读

- 阶段目标：围绕当前模块和设计决策提取关键参数。
- 关键进入条件：用户提供当前候选器件 PDF 或官方资料链接。
- 关键退出条件：关键参数、限制条件和待核对项已记录。
- 特殊风险或例外：立创商品页不能替代 datasheet；不读取无关模块资料。

### 阶段 5：模块电路草图 / 设计说明

- 阶段目标：把关键资料转化为模块连接思路、参数计算和待验证项。
- 关键进入条件：当前模块关键器件和资料依据已基本明确。
- 关键退出条件：`design_notes.md` 中有可用于画原理图的模块说明。
- 特殊风险或例外：可画概念草图，不创建正式 Altium 工程。

### 阶段 6：外围器件参数反推

- 阶段目标：根据关键器件要求反推阻容、保护、接口、封装和测试点需求。
- 关键进入条件：模块设计说明和关键 datasheet 已可支撑参数反推。
- 关键退出条件：外围参数记录和 BOM 草稿依据已形成。
- 特殊风险或例外：普通阻容可按规格和工艺选择，关键保护和接口器件仍需资料核对。

### 阶段 7：BOM 草稿

- 阶段目标：把候选器件和外围参数整理成可核对的非最终 BOM。
- 关键进入条件：关键候选、外围参数和资料路径已有记录。
- 关键退出条件：BOM 草稿标明风险、待核对项、封装和采购可得性状态。
- 特殊风险或例外：未经 datasheet、封装库和采购可得性核对，不得作为最终 BOM。

### 阶段 8：原理图设计

- 阶段目标：在 EDA 中实现第一版原理图，并输出可审查证据。
- 关键进入条件：需求、模块说明、关键资料和 BOM 草稿足以支撑绘制。
- 关键退出条件：当前 Altium 原理图已保存并完成版本标识，至少导出可追溯到当前 `.SchDoc` 版本的完整原理图 PDF，并准备当前版本 BOM；BOM 至少包含位号、数量、参数或型号、PCB 封装。关键器件应尽量包含明确型号或料号，通用阻容、LED、测试点和排针不强制具体制造商料号，不得虚构料号。网表、ERC 输出、元件报告、封装映射报告和局部截图按问题类型条件触发；AI 只有在用户提供 ERC 报告、Messages 导出或相关截图时才分析 ERC 问题。
- 特殊风险或例外：AI 可提供连接检查思路，正式工程由用户在 EDA 中绘制。

### 阶段 9：原理图审查

- 阶段目标：进入 PCB Layout 前排除高风险连接、参数、保护、封装和调试问题。
- 关键进入条件：默认至少具备可追溯到当前 `.SchDoc` 版本的完整原理图 PDF，以及当前版本 BOM。完整原理图 PDF 和当前版本 BOM 可以支持常规原理图系统审查；无法由二者确认的实际网络、引脚映射、封装映射或其他 EDA 实现事项，应说明结论限制或标记为“待 EDA 核对”。涉及复杂网络、跨页网络、器件属性不足或关键引脚 / 封装映射风险的问题，应提供与问题类型匹配的附加证据。
- 关键退出条件：`docs/schematic_review.md` 记录结论、问题、风险等级和关闭条件。
- 特殊风险或例外：局部截图只能补充局部证据，不能代替完整原理图 PDF；不得使用与当前 `.SchDoc` 版本不一致的输出混合关闭问题；无可靠实现证据的问题应标记“待 EDA 核对”。

### 阶段 10：PCB Layout

- 阶段目标：完成布局布线，控制回流路径、敏感信号、大电流和可调试性风险。
- 关键进入条件：关键原理图审查已经完成，所有高风险问题已经关闭；“待验证”“待 EDA 核对”或证据不足的高风险问题均视为未关闭；未关闭的中、低风险问题已有明确处置方案，并确认不会影响板级安全、封装选择、接口定义和 PCB 关键布局。
- 关键退出条件：PCB 工程、布局布线说明和必要制造约束已形成。
- 特殊风险或例外：原理图不是本阶段主要输出，但发现问题时可回修。

### 阶段 11：PCB 审查

- 阶段目标：打样前检查制造、焊接、回流、间距、丝印和测试点风险。
- 关键进入条件：PCB 初版布局布线完成，设计规则和制造约束明确。
- 关键退出条件：`docs/pcb_review.md` 记录问题、风险等级和修改建议。
- 特殊风险或例外：涉及关键封装和 layout 要求时回到 datasheet 或封装资料核对。

### 阶段 12：打样

- 阶段目标：输出并核对 Gerber、钻孔、BOM、坐标和制造说明。
- 关键进入条件：PCB 审查关键问题已处理。
- 关键退出条件：制造输出包完整，下单参数和版本记录清楚。
- 特殊风险或例外：下单 BOM 仍需最终前核对封装、采购和替代料风险。

### 阶段 13：焊接

- 阶段目标：按风险顺序完成装配并记录异常。
- 关键进入条件：PCB、BOM、装配图和关键极性资料已准备。
- 关键退出条件：焊接记录、照片和异常记录完整。
- 特殊风险或例外：极性器件、接口方向和电源短路必须先检查。

### 阶段 14：上电调试

- 阶段目标：安全验证电源、复位、下载、通信、ADC 和输出功能。
- 关键进入条件：焊接完成，短路检查和 bringup 计划已准备。
- 关键退出条件：`docs/bringup_log.md` 记录实测电压、电流、现象和异常。
- 特殊风险或例外：首次上电必须限流；异常排查时按需回到 datasheet 和原理图。

### 阶段 15：测试报告

- 阶段目标：整理测试条件、步骤、数据、异常和结论。
- 关键进入条件：bringup 已有可复盘记录，测试数据或照片已准备。
- 关键退出条件：`docs/test_report.md` 能支持项目复盘和后续改版判断。
- 特殊风险或例外：不生成 BOM，不改写未验证的功能结论。

### 阶段 16：改版记录

- 阶段目标：把审查、调试和测试问题转化为下一版修改依据。
- 关键进入条件：已有问题记录、测试报告或用户确认的改版需求。
- 关键退出条件：`docs/revision_history.md` 记录原因、影响范围、修改方案和验证项。
- 特殊风险或例外：需要回修原理图或 PCB 时，回到对应阶段重新审查。

### 阶段 17：简历整理

- 阶段目标：基于真实完成记录提炼 README 或简历项目描述。
- 关键进入条件：项目文档、测试结果和实际职责边界可追溯。
- 关键退出条件：描述不夸大、不伪造，通过文档和测试记录可支撑。
- 特殊风险或例外：不把未完成或未验证内容写成已实现成果。

## 5. 使用规则

需要读取本文的场景：

- 用户询问硬件项目完整流程；
- 需要判断当前项目处于哪个阶段；
- 新项目初始化或维护流程文档；
- 阶段边界不清楚；
- 需要判断某阶段是否允许生成 BOM、是否允许画原理图、是否需要 datasheet。

不需要默认读取本文的场景：

- 普通 datasheet 阅读；
- 普通器件选型；
- 单次原理图审查；
- PCB 审查；
- 调试记录整理；
- README 或单个项目文档的小幅维护。

这些普通任务应按 `docs/AI_Context_Guide.md` 读取当前项目、当前阶段 Skill 和被修改文件，避免把完整流程文档塞入上下文。
