# 项目工作流程

## 0. 总原则

本仓库采用渐进式硬件设计流程。

资料收集不是独立的一次性前置阶段。不要先把所有元器件 datasheet 一次性收集完再开始设计；更合理的做法是：先明确需求和模块，再围绕当前设计决策选择关键器件候选，阅读关键 datasheet / reference manual / application note，随后反推外围参数、保护器件、接口器件和 BOM 草稿。

立创商城 / 嘉立创生态主要由用户手动搜索、筛选、检查库存/价格/封装/基础库状态和下载 datasheet。AI/Codex 负责提供搜索关键词、筛选条件、候选记录模板、资料整理、参数提取、候选对比、风险提示和待核对项，不默认自动爬取或批量下载立创商城资料。

## 1. 阶段总览

| 阶段 | 输入文件 | 输出文件 | AI/Codex 职责 | 用户职责 | 需要立创商城 | 需要 datasheet | 允许生成 BOM | 允许画原理图 |
|---|---|---|---|---|---|---|---|---|
| 1. 需求定义 | 项目想法、约束 | `requirements.md` | 梳理目标、边界、接口、电源、风险 | 确认需求和优先级 | 否 | 否 | 否 | 否 |
| 2. 模块方案拆分 | `requirements.md` | `block_diagram.md`、`design_notes.md` | 拆分功能模块、接口边界和风险模块 | 确认模块取舍 | 否 | 否 | 否 | 否 |
| 3. 第一轮关键器件候选选型 | `requirements.md`、`design_notes.md`、`references.md` | `docs/component_selection_plan.md`、候选表 | 给关键词、筛选条件、候选表结构和风险点 | 手动搜索立创、挑候选、下载资料 | 是 | 候选资料按需 | 否，只能候选表 | 否 |

| 5. 模块电路草图 / 设计说明 | 需求、候选参数 | `design_notes.md` | 整理模块电路思路、关键计算、待核对项 | 确认设计方向 | 按需 | 是 | 否 | 可画草图说明，不画正式工程 |

| 7. BOM 草稿 | 候选表、外围参数 | BOM 草稿 | 整理非最终 BOM、标风险和待核对 | 核对采购、封装、库存 | 是 | 关键器件必须 | 允许草稿 | 否 |
| 8. 原理图设计 | 需求、设计说明、关键资料、BOM 草稿 | Altium 原理图、PDF 输出 | 提供连接检查思路和关键参数提醒 | 在 EDA 中绘制并检查 | 按需 | 是 | 可同步更新草稿 | 是 |

| 10. PCB Layout | 已审原理图、封装、结构约束 | PCB 工程、布局布线说明 | 提供布局、回流路径、间距和测试点建议 | 在 EDA 中布局布线 | 按需 | 关键封装和 layout 要求 | 可更新 | 否，转为 PCB |
| 11. PCB 审查 | PCB、规则、制造约束 | `docs/pcb_review.md` | 检查线宽、间距、回流、丝印、测试点 | 修正 PCB | 按需 | 按需 | 可更新 | 否 |
| 12. 打样 | Gerber、BOM、坐标、工艺参数 | 下单记录、制造输出 | 检查输出完整性和风险点 | 用户下单 | 是 | 封装/工艺按需 | 最终前核对 | 否 |
| 13. 焊接 | PCB、BOM、装配资料 | 焊接记录、照片 | 生成焊接顺序和检查表 | 焊接并记录异常 | 按需补料 | 按需 | 可记录替代料 | 否 |

| 15. 测试报告 | 调试记录、测试数据 | `docs/test_report.md` | 整理测试条件、结果、异常和结论 | 执行测试 | 否 | 按需 | 否 | 否 |

## 2. 需求定义

- 输入文件：项目想法、约束、已有需求草稿。
- 输出文件：`requirements.md`。
- AI/Codex：整理目标功能、电源范围、接口数量、机械边界、调试方式、第一版取舍和风险模块。
- 用户：确认项目目标、可接受复杂度、时间和成本边界。
- 立创商城：不需要。
- datasheet：通常不需要。
- BOM：不允许生成。
- 原理图：不允许画正式原理图。

## 3. 模块方案拆分

- 输入文件：`requirements.md`。
- 输出文件：`block_diagram.md`、`design_notes.md`。
- AI/Codex：拆分 MCU、电源、USB、通信、ADC、MOSFET 输出、接口/人机/测试点等模块，标注模块间信号和电源边界。
- 用户：确认模块是否符合第一版目标。
- 立创商城：不需要。
- datasheet：不需要读取所有 datasheet。
- BOM：不允许生成。
- 原理图：不允许画正式原理图。

## 4. 第一轮关键器件候选选型

- 输入文件：`requirements.md`、`design_notes.md`、`references.md`。
- 输出文件：`docs/component_selection_plan.md`、候选器件记录表。
- AI/Codex：识别关键器件类别，给出立创搜索关键词、筛选条件、比较维度、风险点和待核对项。
- 用户：在立创商城手动搜索，每类先挑 2-3 个候选，检查库存、价格、封装、基础库/扩展库状态，并下载 datasheet。
- 立创商城：需要，但由用户手动使用。
- datasheet：只需要当前关键候选资料。
- BOM：不允许生成最终 BOM，只允许候选记录表。
- 原理图：不允许画。

第一轮重点是关键器件，不是普通外围器件。普通阻容、LED、按键、排针、测试点和跳帽后置。

## 5. 关键 datasheet 阅读

- 输入文件：当前模块候选器件 datasheet、reference manual 或 application note。
- 输出文件：参数提取表、`references.md` 更新建议、`design_notes.md` 更新建议。
- AI/Codex：只提取与当前设计决策相关的参数，例如电源范围、封装、引脚、典型应用、电容要求、热耗散、驱动条件和 PCB Layout 要点。
- 用户：提供本地 PDF 或官方链接，确认器件型号和版本。
- 立创商城：可作为资料入口，但不能替代 datasheet。
- datasheet：需要，仅限当前模块和当前候选。
- BOM：不允许生成最终 BOM。
- 原理图：不允许画正式原理图。

## 6. 模块电路草图 / 设计说明

- 输入文件：需求、模块划分、关键 datasheet 提取结果。
- 输出文件：`design_notes.md` 中的模块设计说明，必要时附草图或连接说明。
- AI/Codex：说明模块连接、关键参数来源、风险点、待计算项和待验证项。
- 用户：确认模块电路方向是否符合练习目标和可焊接性。
- 立创商城：按需补充候选器件。
- datasheet：需要，围绕关键器件和当前设计问题。
- BOM：不允许生成最终 BOM。
- 原理图：可做概念草图或文字说明，不创建正式 Altium 工程。

## 7. 外围器件参数反推

- 输入文件：关键器件 datasheet、模块设计说明、接口边界。
- 输出文件：外围参数记录、BOM 草稿依据。
- AI/Codex：根据关键器件要求反推去耦电容、输入输出电容、分压电阻、限流电阻、栅极电阻、下拉电阻、保护器件、接口器件和测试点要求。
- 用户：根据建议手动搜索外围器件，确认封装、库存和价格。
- 立创商城：按需。
- datasheet：关键外围器件需要，普通阻容通常按规格和工艺要求选择。
- BOM：允许生成 BOM 草稿依据，不允许最终定版。
- 原理图：不允许直接跳过审查画正式图。

## 8. BOM 草稿

- 输入文件：关键候选表、外围参数记录、datasheet 核对结果。
- 输出文件：BOM 草稿。
- AI/Codex：整理候选、替代、风险等级、待核对项和资料路径。
- 用户：确认采购可得性、封装库、价格和是否进入下一轮。
- 立创商城：需要手动核对。
- datasheet：关键器件必须核对。
- BOM：允许草稿，不允许最终 BOM。
- 原理图：不允许画。

## 9. 原理图设计

- 输入文件：需求、设计说明、关键资料、BOM 草稿。
- 输出文件：Altium 原理图、PDF 原理图输出。
- AI/Codex：提供连接关系、关键网络、测试点、风险项和 datasheet 核对提醒。
- 用户：在 EDA 中绘制原理图并处理封装库。
- 立创商城：按需核对封装和库状态。
- datasheet：需要。
- BOM：可同步更新草稿。
- 原理图：允许。

## 10. 原理图审查

- 输入文件：原理图、设计说明、关键 datasheet、候选记录。
- 输出文件：`docs/schematic_review.md`。
- AI/Codex：按 checklist 审查供电、复位、时钟、BOOT、SWD、USB、UART、ADC、MOSFET、保护、测试点和封装。
- 用户：修改原理图并记录结论。
- 立创商城：按需确认封装和可采购性。
- datasheet：需要。
- BOM：可更新草稿。
- 原理图：允许修改。

## 11. PCB Layout

- 输入文件：已审原理图、封装、板框、接口位置和制造约束。
- 输出文件：PCB 工程、布局布线说明。
- AI/Codex：提供布局顺序、回流路径、敏感信号、电源路径、测试点和丝印建议。
- 用户：在 EDA 中完成 Layout。
- 立创商城：按需确认封装。
- datasheet：关键封装和 layout 要求需要核对。
- BOM：可更新。
- 原理图：不作为主要输出。

## 12. PCB 审查

- 输入文件：PCB、设计规则、制造约束、原理图。
- 输出文件：`docs/pcb_review.md`。
- AI/Codex：检查线宽、间距、回流路径、去耦位置、保护器件位置、安装孔、丝印、测试点和制造输出。
- 用户：修正 PCB 并重新生成输出。
- 立创商城：按需。
- datasheet：按需。
- BOM：可更新。
- 原理图：通常不画，必要时回修。

## 13. 打样

- 输入文件：Gerber、钻孔、BOM、坐标、PDF、制造说明。
- 输出文件：制造输出包、下单记录。
- AI/Codex：检查输出完整性、版本命名、工艺参数和风险提醒。
- 用户：下单并保留下单信息。
- 立创商城：可能需要采购和 SMT 核对。
- datasheet：按需。
- BOM：允许形成下单版本。
- 原理图：不画。

## 14. 焊接

- 输入文件：PCB、BOM、装配图、原理图。
- 输出文件：焊接记录、装配照片、异常记录。
- AI/Codex：给出分阶段焊接顺序和电阻短路检查项。
- 用户：焊接、拍照、记录异常。
- 立创商城：按需补料。
- datasheet：按需核对极性和封装。
- BOM：可记录替代料。
- 原理图：不画。

## 15. 上电调试

- 输入文件：焊接完成板、原理图、调试计划。
- 输出文件：`docs/bringup_log.md`。
- AI/Codex：制定限流上电、电源轨、复位、时钟、下载、串口、ADC、MOSFET 输出的分步检查计划。
- 用户：执行测试并记录电压、电流、波形和异常。
- 立创商城：不需要。
- datasheet：异常排查时按需。
- BOM：不生成。
- 原理图：不画，必要时标注问题。

## 16. 测试报告

- 输入文件：测试数据、bringup 记录、固件版本。
- 输出文件：`docs/test_report.md`。
- AI/Codex：整理测试条件、仪器、步骤、结果、异常、结论和下一步。
- 用户：补充实际测试数据和照片。
- 立创商城：不需要。
- datasheet：按需。
- BOM：不生成。
- 原理图：不画。

## 17. 改版记录

- 输入文件：审查记录、测试报告、问题清单。
- 输出文件：`docs/revision_history.md`。
- AI/Codex：整理问题现象、原因分析、修改方案、影响范围和验证计划。
- 用户：确认是否改版和优先级。
- 立创商城：按需。
- datasheet：按需。
- BOM：可更新。
- 原理图：必要时回修。

## 18. 简历整理

- 输入文件：README、设计说明、测试报告、改版记录。
- 输出文件：README 项目亮点、简历项目描述。
- AI/Codex：提炼真实目标、职责、技术点、调试问题和结果。
- 用户：确认真实性和表达边界。
- 立创商城：不需要。
- datasheet：不需要。
- BOM：不生成。
- 原理图：不画。
