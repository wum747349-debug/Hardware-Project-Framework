# 硬件项目八阶段工作流程

> 文档状态：当前有效
> 适用阶段：全部八阶段
> 适用对象：本仓库硬件项目
> 最后核对依据：`PROJECT_RULES.md`、`docs/Project_Structure_Standard.md`

## 1. 文档定位

本文是仓库标准执行流程，规定硬件项目八个主阶段的顺序、输入、活动、输出、职责和阶段门。它用于判断当前阶段、进入和退出条件，以及何时应回退上游阶段；不是普通任务的默认上下文，也不替代项目事实文件、Skill 或 checklist。

普通任务先按 `docs/AI_Context_Guide.md` 读取最小必要上下文。项目结构和文件职责以 `docs/Project_Structure_Standard.md` 为准，稳定原则和安全边界以 `PROJECT_RULES.md`、`AGENTS.md` 为准。

## 2. 总原则

- 本仓库采用渐进式硬件设计：先确认需求和模块边界，再围绕当前决策选择关键器件、读取资料、反推外围、形成 BOM 草稿和 EDA 实现。
- datasheet 阅读是各阶段按当前决策触发的工具型活动，不是独立顶层阶段。
- 规则文件描述“应该是什么”，审查记录描述“实际是否做到”。
- 阶段文档存在不代表阶段已经完成；必须满足退出条件并记录证据或用户确认。
- AI/Codex 负责分析、建议、文档、检查输入和 Git 维护；用户负责 Altium Designer 操作、原理图绘制、PCB 规则配置、布局布线、铺铜、Repour、ERC、DRC、制造输出、焊接和实测。
- `.SchDoc` 和 `.PcbDoc` 分别是原理图与 PCB 的权威实现源文件。无可靠解析能力时，AI 不得声称读取或核对其内部对象。
- 任何关键依据、实现证据或测试证据不足的结论，必须说明限制或标记“待 EDA 核对”“待用户确认”“待实测”。

## 3. 八阶段总览

| 阶段 | 主阶段 | 主要输出 | 核心阶段门 |
|---|---|---|---|
| 1 | 需求确认阶段 | `requirements.md`、`block_diagram.md`、设计边界 | 第一版范围和基础 PCB 规格明确 |
| 2 | 关键器件选型阶段 | 主选/备选、选型记录、资料索引 | 影响架构与布局的关键器件有依据 |
| 3 | 原理图模块设计和绘制阶段 | 模块文档、BOM 草稿、原理图及审查输出 | 可追溯的原理图 PDF 与当前 BOM 可供审查 |
| 4 | 原理图审查阶段 | `docs/schematic_review.md` | 高风险问题关闭，关键布局输入明确 |
| 5 | PCB 布局阶段 | 项目级规则基线、已核对规则、正式布局 | Layout Preflight 全部满足 |
| 6 | 布线和铺铜阶段 | 完成布线与铺铜的 PCB、阶段性 DRC 记录 | 无未处理关键问题，具备 PCB 审查输入 |
| 7 | PCB 审查阶段 | `docs/pcb_review.md`、制造输出、放行结论 | 完整 Batch DRC 和制造放行门禁满足 |
| 8 | 焊接和硬件调试阶段 | `bringup_log.md`、`test_report.md`、`revision_history.md` | 安全上电、功能验证和问题回溯完成 |

原有活动归属：

| 原有活动 | 新归属 |
|---|---|
| 模块方案拆分 | 阶段 1 |
| datasheet 阅读 | 阶段 2、3 及后续按需活动 |
| 外围器件参数反推 | 阶段 3 |
| BOM 草稿 | 阶段 3 输出 |
| 打样和制造输出 | 阶段 7 退出活动 |
| 测试报告 | 阶段 8 输出 |
| 改版记录 | 阶段 8 输出，并按影响回退相关设计阶段 |
| 简历整理 | 项目完成后的仓库维护任务，不是硬件主阶段 |

## 4. 阶段 1：需求确认阶段

### 阶段目标

明确第一版做什么、不做什么，完成模块方案拆分，并建立电源、接口、负载、模拟、安全、调试、机械和基础制造边界。

### 默认输入

- 项目想法、应用场景和用户约束；
- 成本、尺寸、采购、手工焊接或 SMT 等约束；
- 已知接口、电源、负载和安全要求。

### 阶段内主要活动

- 确认功能目标、第一版范围和明确不做的内容；
- 拆分功能模块，整理能量流、信号流和模块边界；
- 确认输入输出电压、电流、负载类型、模拟范围、通信接口和调试方式；
- 识别电源、电池、MOSFET、模拟输入、接口误接和首次上电等风险；
- 确认目标板厂、PCB 材料、层数、成品板厚、铜厚和装配方式；
- 记录板框、安装孔和连接器位置的初步约束；
- 明确是否声明受控阻抗；不需要时显式记录“不声明”；
- 将尚未确定的事项标记为待确认，不在需求阶段直接确定所有 PCB 细节规则值。

### 主要输出

- `requirements.md`；
- `block_diagram.md`；
- 项目 `README.md` 的范围与当前阶段摘要；
- `design_notes.md` 的整板结构入口和待确认项。

### AI/Codex 职责

- 梳理需求、边界、模块、风险和待确认问题；
- 区分必须现在决策与可在后续阶段决策的事项；
- 维护项目事实文件和链接，不虚构制造规格。

### 用户职责

- 确认用途、优先级、第一版取舍和验收边界；
- 确认目标板厂、装配方式和机械约束；
- 对安全、成本和采购假设作最终确认。

### 进入条件

- 已有可描述的项目目标或问题；
- 能联系到需求确认人。

### 退出条件

- 第一版功能和不做内容已明确；
- 模块边界、主要电源和接口已建立；
- 目标板厂和基础 PCB 规格已确认，或待确认项有负责人和核对计划；
- 验收边界足以支撑关键器件选型。

### 允许和禁止事项

- 允许建立模块候选方向和资料需求。
- 禁止直接生成最终 BOM 或正式原理图。
- 禁止把板厂极限值直接作为推荐默认设计值。
- 禁止为了结束本阶段而虚构板框、安装孔或制造规格。

### Skill 与 checklist

- 默认不要求读取全部 Skill；
- 涉及专项安全边界时按需使用相应 checklist；
- 新项目初始化遵循 `docs/Project_Structure_Standard.md` 和 `docs/Project_Template_Guide.md`。

### 回退上游阶段的情况

本阶段没有上游硬件阶段。后续若功能范围、接口、电源、机械、板厂或验收边界发生变化，必须回到本阶段更新需求并评估下游影响。

## 5. 阶段 2：关键器件选型阶段

### 阶段目标

围绕当前架构决策选择影响供电、外围、封装、布局、散热和采购的关键器件，形成有依据的主选与备选。

### 默认输入

- `requirements.md`；
- `block_diagram.md`；
- `design_notes.md`；
- `references.md`；
- 当前模块的采购和封装约束。

### 阶段内主要活动

- 识别会改变架构或 PCB 约束的关键器件类别；
- 为每类关键器件建立筛选条件、主选、备选和淘汰理由；
- 只围绕当前决策读取相关 datasheet、reference manual 或 application note；
- 核对工作范围、绝对最大值、典型应用、外围要求、封装、引脚和 Layout 要求；
- 记录资料来源、版本、阅读状态和待核对项；
- 评估采购可得性、封装可焊性和替代料风险；
- 将普通阻容、LED、排针、测试点等不影响架构的器件后置。

### 主要输出

- `docs/component_selection_plan.md`；
- `references.md` 更新；
- `design_notes.md` 中的主选/备选摘要；
- 关键参数提取和风险记录。

### AI/Codex 职责

- 提供搜索关键词、比较维度、风险分类和资料提取；
- 检查候选是否满足需求并指出待核对参数；
- 维护选型依据，不把商品页当作关键参数唯一依据。

### 用户职责

- 进行实际采购平台搜索、下载资料并确认候选型号；
- 确认成本、库存、封装和焊接可行性；
- 对主选和备选作最终决策。

### 进入条件

- 阶段 1 的功能、模块和基础制造边界足以筛选器件；
- 当前需要决策的关键器件类别已明确。

### 退出条件

- 影响架构、外围、封装和关键布局的器件有主选与合理备选；
- 关键参数和 Layout 要求已从可靠资料核对或明确标记待核对；
- 未把候选表误写为最终 BOM。

### 允许和禁止事项

- 允许形成候选表和主选/备选结论。
- 允许按当前决策分批补充资料。
- 禁止一次性要求收集全部 datasheet。
- 禁止生成未经 datasheet、封装和采购可得性核对的最终 BOM。

### Skill 与 checklist

- 默认调用 `skills/hardware-component-selection/SKILL.md`；
- 读取关键资料时调用 `skills/hardware-datasheet-reading/SKILL.md`；
- 专项安全与模拟风险按需路由到对应 checklist。

### 回退上游阶段的情况

- 没有任何候选满足需求；
- 器件导致成本、尺寸、层数、供电、接口或装配方式发生实质变化；
- 关键器件停产或不可采购，需要修改需求或模块架构。

## 6. 阶段 3：原理图模块设计和绘制阶段

### 阶段目标

根据关键器件主选/备选反推模块电路、外围参数和专项布局要求，并由用户在 Altium Designer 中完成正式原理图。

### 默认输入

- 阶段 1 的需求与模块边界；
- 阶段 2 的主选、备选和关键资料；
- 当前 `design_notes.md`、`references.md`；
- 关键器件 datasheet 与应用资料。

### 阶段内主要活动

- 为每个模块整理供电、信号、保护、调试和跨模块接口；
- 根据 datasheet 反推阻容、去耦、偏置、保护、时钟、复位、滤波和接口参数；
- 核对器件引脚、封装、极性、额定值和 Pin/Pad mapping 风险；
- 在 `docs/module_design/*.md` 记录模块连接、计算、器件依据和专项布局要求；
- 在 `design_notes.md` 维护整板主选方案、Pin Map、接口定义和跨模块约定；
- 形成带风险、封装和待核对项的 BOM 草稿；
- 用户在 Altium Designer 中绘制、保存和版本化正式原理图；
- 导出可追溯到当前 `.SchDoc` 的完整原理图 PDF 和当前版本 BOM。

### 主要输出

- `docs/module_design/*.md`；
- 更新后的 `design_notes.md` 与 `references.md`；
- BOM 草稿；
- Altium `.SchDoc`；
- 完整原理图 PDF；
- 当前版本 BOM。

### AI/Codex 职责

- 提供连接思路、计算方法、参数提醒、风险检查和文档协作；
- 核对用户提供的资料和导出证据；
- 不声称在 Altium 中完成绘制或验证。

### 用户职责

- 在 Altium Designer 中创建和维护正式原理图；
- 核对符号、封装、引脚、网络和器件属性；
- 实际执行 ERC（如需要）并导出审查证据；
- 确认 BOM 草稿中的采购和封装信息。

### 进入条件

- 关键器件主选/备选足以确定模块电路方向；
- 关键资料能够支撑当前模块连接和参数反推。

### 退出条件

- 模块设计说明能追溯关键连接和参数依据；
- BOM 草稿包含位号、数量、参数或型号、PCB 封装和必要风险；
- 已提供可追溯到当前 `.SchDoc` 版本的完整原理图 PDF 和当前版本 BOM；
- 关键器件型号、封装和专项 Layout 要求已明确或有具体待核对计划。

### 允许和禁止事项

- 允许生成 BOM 草稿并随原理图迭代。
- 允许在发现资料问题时回到阶段 2。
- 禁止将 BOM 草稿描述为最终 BOM。
- 禁止 AI 声称已读取无法可靠解析的 `.SchDoc` 内部电路。

### Skill 与 checklist

- 按需调用 `skills/hardware-datasheet-reading/SKILL.md`；
- 按需调用 `skills/hardware-component-selection/SKILL.md`；
- 使用原理图和专项模块 checklist 辅助设计自查。

### 回退上游阶段的情况

- 关键器件参数、封装或采购状态不满足设计；
- 外围反推显示原需求或架构不可实现；
- 原理图绘制暴露接口、电源或模块边界冲突。

## 7. 阶段 4：原理图审查阶段

### 阶段目标

在 PCB Layout 前发现并关闭供电、接口、保护、封装、引脚、板级安全和关键布局输入问题。

### 默认输入

- 可追溯到当前 `.SchDoc` 的完整原理图 PDF；
- 当前版本 BOM，至少包含位号、数量、参数或型号和 PCB 封装；
- `requirements.md`、`design_notes.md`、`references.md`；
- 当前模块文档；
- 已有 `docs/schematic_review.md`。

### 阶段内主要活动

- 按电源、MCU、接口、模拟、驱动、保护、调试和封装顺序审查；
- 核对关键器件资料和模块设计意图；
- 记录问题、证据、风险等级、修改建议、关闭条件和状态；
- 对复杂网络、引脚或封装映射问题按需请求网表、元件报告或映射证据；
- 仅在用户提供 ERC 报告、Messages 导出或截图时分析 ERC 问题；
- 确认所有会影响封装、接口、板级安全和关键布局的问题均已处理。

### 主要输出

- `docs/schematic_review.md`；
- 必要的 `design_notes.md`、模块文档、BOM 草稿或需求同步；
- 是否允许进入 PCB Layout Preflight 的结论。

### AI/Codex 职责

- 依据 PDF、BOM 和条件触发证据进行系统审查；
- 明确证据限制和“待 EDA 核对”项；
- 不把文档设计意图当作 EDA 已同步的证明。

### 用户职责

- 在 Altium Designer 中实际修改和复核原理图；
- 重新导出同版 PDF、BOM 或与问题匹配的证据；
- 对 ERC、符号、封装、Pin/Pad mapping 和 EDA 实现作最终确认。

### 进入条件

- 默认审查证据齐全且可追溯到同一原理图版本；
- 原理图已经达到可进行系统审查的完整度。

### 退出条件

- 所有高风险问题已关闭；
- 影响封装、接口、板级安全和关键布局的问题不得遗留；
- 未关闭的中低风险问题有明确处置方案，且不阻断 PCB 关键决策；
- 审查记录明确给出“允许进入 PCB Layout Preflight”或阻断结论。

### 允许和禁止事项

- 允许在审查中回修原理图并重复审查。
- ERC 不是默认必需输入，未提供 ERC 不能单独作为禁止进入 PCB Layout 的理由。
- 禁止以局部截图替代完整原理图 PDF。
- 禁止在实现证据不足时标记问题“已关闭”。

### Skill 与 checklist

- 默认调用 `skills/hardware-schematic-review/SKILL.md`；
- 使用 `checklists/schematic_checklist.md` 及项目类型对应 checklist；
- 关键参数争议按需调用 datasheet Skill。

### 回退上游阶段的情况

- 器件选型依据或封装不成立时回到阶段 2；
- 模块连接和外围参数需要重做时回到阶段 3；
- 功能、安全或接口边界发生变化时回到阶段 1。

## 8. 阶段 5：PCB 布局阶段

### 阶段目标

在正式布局前完成制造、机械、封装和规则准备，并按功能分区、关键路径和可装配性完成器件布局。

### 默认输入

- 已通过阶段门的原理图审查记录；
- `requirements.md`、`design_notes.md`、`references.md`；
- 关键模块文档、关键封装和器件 Layout 要求；
- 目标板厂官方制造能力；
- 当前 `.PcbDoc` 与项目 `docs/pcb_design_rules.md`。

### Layout Preflight 强制阶段门

```text
[ ] 目标板厂已确认
[ ] 板材、层数、板厚、铜厚已确认
[ ] 板框和安装孔已确认或有明确待核对计划
[ ] 关键封装已核对
[ ] 关键器件机械和 Layout 要求已读取
[ ] 网络分类或明确 Scope 已规划
[ ] docs/pcb_design_rules.md 已完成
[ ] Altium 实际规则已配置
[ ] Scope 和 Priority 已核对
[ ] 初始 DRC 已运行
[ ] 原理图高风险问题已关闭
```

只有全部满足并由用户确认后，项目才能标记“允许正式布局”。若某项不适用，必须记录不适用依据，不能直接留空视为通过。

### 阶段内主要活动

- 建立板框、安装孔、禁布区、高度和连接器可达性约束；
- 核对关键封装、Pin/Pad mapping、极性、Pin 1 和机械模型；
- 整理制造基线与设计默认值，保留合理制造裕量；
- 规划网络分类、Net Class 或明确网络 Scope；
- 在 `docs/pcb_design_rules.md` 定义规则值、Scope、Priority 和 DRC 类别；
- 用户在 Altium Designer 中配置实际规则并核对覆盖关系；
- 完成功能分区、电源入口、关键器件、连接器、晶振、模拟、功率与去耦布局；
- 评估回流路径、散热、装配、返修、探测和板边风险。

### 主要输出

- 已完成并核对的 `docs/pcb_design_rules.md`；
- Layout Preflight 记录；
- 初始 DRC 用户确认；
- 完成关键器件与功能分区布局的 `.PcbDoc`；
- 必要的 PCB 图片或机械证据。

### AI/Codex 职责

- 协助整理制造能力、设计默认值、网络分类、Scope、Priority 和布局顺序；
- 基于用户提供的规则摘要、截图、图片和资料进行辅助审查；
- 证据不足时标记“待 EDA 核对”。

### 用户职责

- 在 Altium Designer 中核对板框、封装和机械约束；
- 实际配置规则、Scope 和 Priority；
- 运行初始 DRC；
- 实际摆放器件并确认布局。

### 进入条件

- 阶段 4 已允许进入 PCB Layout Preflight；
- 具备目标板厂、机械、封装和规则准备所需资料。

### 退出条件

- Layout Preflight 全部满足；
- 关键器件、连接器、安装孔、板边和主要功能分区布局已确认；
- 关键电源、模拟、高速、晶振、MOSFET 和负载回路的布局方向明确；
- 不存在阻断布线的机械、封装或规则问题。

### 允许和禁止事项

- 允许在布局中发现问题后回修原理图。
- 允许简单、明确的网络直接使用专项 Scope，不强制创建无实际需要的复杂 Net Class。
- 禁止在规则文档、实际规则或初始 DRC 未准备时标记“允许正式布局”。
- 禁止把 PCB 图片当作间距、孔径、环宽、网络或 DRC 通过的证明。

### Skill 与 checklist

- 默认调用 [PCB Layout / Review Skill](../skills/hardware-pcb-layout-review/SKILL.md) 的 Layout Preflight 模式；
- 使用 [PCB Layout Preflight Checklist](../checklists/pcb_layout_preflight_checklist.md)；
- 关键器件布局要求按需调用 datasheet Skill。

### 回退上游阶段的情况

- 封装或 Pin/Pad mapping 不成立时回到阶段 2 或 3；
- 原理图网络、接口或保护需要修改时回到阶段 3，并重新经过阶段 4；
- 板框、层数、成本或制造基线变化时回到阶段 1；
- 高风险原理图问题重新打开时停止布局并回到阶段 4。

## 9. 阶段 6：布线和铺铜阶段

### 阶段目标

完成符合项目规则和信号/电源完整性基本要求的布线、换层、回流路径和铺铜，为 PCB 审查提供可追溯实现证据。

### 默认输入

- 已通过 Layout Preflight 的布局；
- 项目 `docs/pcb_design_rules.md`；
- 关键器件与模块专项 Layout 要求；
- 网络分类、Scope、Priority 和当前 DRC 基线。

### 阶段内主要活动

- 优先处理关键电源、负载和大电流回路；
- 处理模拟、数字、晶振、高速、USB 和敏感区域的隔离与回流路径；
- 控制 MOSFET、续流和外部负载回路面积；
- 按规则选择线宽、间距、过孔和换层方式；
- 避免不必要换层、细颈、回流割裂和长距离关键环路；
- 建立 GND 铺铜和必要的地过孔策略；
- 每次相关修改后由用户执行 Repour；
- 运行中间 DRC，检查未布线、短路、间距、线宽、孔和铺铜状态；
- 更新必要的实现图片和待审问题。

### 主要输出

- 已完成布线和铺铜的 `.PcbDoc`；
- 用户确认的 Repour 和中间 DRC 结果；
- 未布线检查结果；
- 必要的顶层、底层和无铺铜视图；
- 进入 PCB 审查的版本标识。

### AI/Codex 职责

- 提供布线顺序、回流路径、换层、铺铜和风险审查建议；
- 分析用户提供的图片、规则摘要和 DRC 结果；
- 记录问题和证据限制。

### 用户职责

- 在 Altium Designer 中实际布线、换层、铺铜和 Repour；
- 实际运行中间 DRC 和未布线检查；
- 修正规则违规或记录待审问题。

### 进入条件

- 阶段 5 已完成且布局不存在阻断问题；
- 项目规则与实际 Altium 规则已配置并核对。

### 退出条件

- 计划网络已完成布线，未布线项为零或有明确、合理且待审的说明；
- GND 铺铜已 Repour；
- 关键回流、功率、模拟、高速、晶振和负载路径已人工检查；
- 中间 DRC 的关键违规已处理；
- 当前 PCB 版本和审查输入可追溯。

### 允许和禁止事项

- 允许在布线中调整布局，但关键器件位置变化后要重新审查相关布局要求。
- 禁止通过关闭必要规则来消除违规。
- 禁止把中间 DRC 当作制造放行的完整 Batch DRC。
- 禁止 AI 声称实际完成布线、Repour 或 DRC。

### Skill 与 checklist

- 默认调用 [PCB Layout / Review Skill](../skills/hardware-pcb-layout-review/SKILL.md) 的 Layout / Routing Review 模式；
- 使用 [通用 PCB Layout Checklist](../checklists/pcb_layout_checklist.md) 和项目专项 checklist；
- 关键问题按需回读 datasheet。

### 回退上游阶段的情况

- 布线暴露封装、板框、规则或布局不可行时回到阶段 5；
- 网络或保护电路错误时回到阶段 3，并重新经过原理图审查；
- 制造规格变化使现有规则失效时回到阶段 1 和阶段 5。

## 10. 阶段 7：PCB 审查阶段

### 阶段目标

审查 PCB 规则、实现、机械、装配和制造输出，形成明确的制造放行或阻断结论。

### 默认输入

- 当前 `.PcbDoc` 的可追溯版本信息；
- `requirements.md`、`design_notes.md`、`references.md`；
- `docs/pcb_design_rules.md` 和已有 `docs/pcb_review.md`；
- PCB 图片、BOM 和关键封装证据；
- 用户运行的完整 Batch DRC 结果；
- 待放行的 Gerber、钻孔、坐标、装配图和制造说明。

### 阶段内主要活动

- 核对项目规则与实际规则、Scope、Priority 和覆盖关系；
- 分析完整 Batch DRC 的 Warnings、Rule Violations 和检查类别；
- 检查未布线、短路、Clearance、Width、Via、Hole Size、Annular Ring、Board Outline 和 Solder Mask；
- 检查板边、安装孔、机械间隙、连接器方向和可达性；
- 检查丝印、极性、Pin 1、位号和装配可读性；
- 核对 BOM、PCB Footprint、替代料和装配面；
- 核对 Gerber、PTH/NPTH 钻孔、坐标、装配图、制造说明和下单参数；
- 记录每个规则豁免的对象、原因、风险、验证方式和批准状态；
- 输出显式制造放行结论。

### PCB 审查前阶段门

- 当前 PCB、BOM、图片和 DRC 结果可追溯到同一版本；
- 布线和铺铜阶段退出条件已满足；
- 未布线和关键中间 DRC 问题已处理；
- 项目规则基线和实际 Altium 规则状态可供核对。

### 制造放行阶段门

- 用户已运行完整 Batch DRC；
- Warnings 和 Rule Violations 均已解决，或有明确、合理、可追溯且已批准的豁免；
- 未布线、短路、板边、安装孔、机械、过孔、丝印、极性、Pin 1、封装和 BOM 已核对；
- Gerber、钻孔、坐标、装配图、制造说明和下单参数齐全且版本一致；
- 规则豁免已记录；
- `docs/pcb_review.md` 给出“批准制造”或“不批准制造”的显式结论；
- 用户对最终 DRC、制造输出和下单参数作最终确认。

### 主要输出

- 更新后的 `docs/pcb_review.md`；
- 完整 Batch DRC 结果记录或引用；
- 规则豁免记录；
- 同版制造输出；
- 制造放行结论和下单参数记录。

### AI/Codex 职责

- 按规则、实现、机械、装配和制造输出顺序辅助审查；
- 分析用户提供的 DRC 与输出文件完整性；
- 记录问题、风险、证据和结论限制；
- 维护审查文档、链接和 Git。

### 用户职责

- 在 Altium Designer 中实际修正 PCB、Repour 并运行完整 Batch DRC；
- 实际导出 Gerber、钻孔、坐标、装配图和制造资料；
- 确认规则豁免、下单参数和最终制造放行；
- 实际向板厂下单。

### 进入条件

- 阶段 6 退出条件满足；
- 审查输入能追溯到当前 PCB 保存状态。

### 退出条件

- 所有高风险问题和制造阻断项关闭；
- 完整 Batch DRC 满足放行要求；
- 制造输出完整、同版且经用户确认；
- 审查记录给出明确制造结论。

### 允许和禁止事项

- 允许审查不通过并回到阶段 5 或 6 修正。
- 允许合理规则豁免，但必须有对象、原因、风险、验证方式和批准记录。
- 禁止用删除规则、扩大容差或忽略报告来伪造 DRC 通过。
- PCB 审查通过不等于 AI 实际运行过 DRC；最终 DRC 和制造输出由用户完成并确认。
- 禁止在证据不足时声称“PCB 已通过”或“可以投产”。

### Skill 与 checklist

- 默认调用 [PCB Layout / Review Skill](../skills/hardware-pcb-layout-review/SKILL.md) 的 PCB Release Review 模式；
- 使用 [PCB Release Checklist](../checklists/pcb_release_checklist.md)；
- 关键封装和器件 Layout 争议按需调用 datasheet Skill。

### 回退上游阶段的情况

- 规则、布局或机械问题回到阶段 5；
- 布线、回流或铺铜问题回到阶段 6；
- 原理图、封装映射或 BOM 源头问题回到阶段 2、3，并重新经过阶段 4；
- 制造规格或功能边界变化回到阶段 1。

## 11. 阶段 8：焊接和硬件调试阶段

### 阶段目标

安全完成装配、首次上电、下载通信、功能和性能验证，形成可追溯调试、测试和改版记录。

### 默认输入

- 已批准制造的 PCB 与同版制造资料；
- 当前 BOM、装配图、原理图和接口说明；
- 关键器件 datasheet；
- 调试设备、固件和测试计划。

### 阶段内主要活动

- 焊接前核对物料、封装、替代料、极性、Pin 1、连接器方向和短路；
- 按风险和返修难度规划焊接顺序；
- 首次上电使用限流电源并记录电压、电流和异常；
- 分电源轨检查输入、保护、稳压、复位和时钟；
- 验证下载、调试、通信、模拟采集、输出驱动和安全边界；
- 记录测试条件、期望、实测值、异常和结论；
- 分析问题根因和临时措施；
- 形成硬件改版记录，并按影响回退需求、选型、原理图或 PCB 阶段。

### 主要输出

- `docs/bringup_log.md`；
- `docs/test_report.md`；
- `docs/revision_history.md`；
- 必要的测试图片、波形和用户说明更新。

### AI/Codex 职责

- 生成焊接前检查和分步调试计划；
- 分析用户提供的测量数据、波形、日志和现象；
- 整理问题、测试报告、改版原因和复验项；
- 不把计划或推测写成已完成实测。

### 用户职责

- 实际焊接、清洁、测量、限流上电和操作仪器；
- 实际执行下载、通信、功能和边界测试；
- 记录原始数据、现象和安全事件；
- 确认测试结论和是否改版。

### 进入条件

- 阶段 7 已明确批准制造；
- 实物、同版 BOM、装配资料和安全调试计划齐全；
- 首次上电保护措施和测量点已准备。

### 退出条件

- 焊接、首次上电和主要电源轨结果已记录；
- 核心功能和验收边界已测试，未测项明确；
- 异常有结论、后续措施或改版计划；
- `bringup_log.md`、`test_report.md` 和必要的 `revision_history.md` 可追溯到硬件版本。

### 允许和禁止事项

- 允许按问题类型回到任何受影响的上游阶段。
- 禁止无人看管的高风险供电或电池测试。
- 禁止无短路检查、无限流保护直接首次上电。
- 禁止把未执行的测试写成通过。

### Skill 与 checklist

- 使用电源、模拟、板级安全和项目专项 checklist；
- 关键异常按需调用 datasheet Skill；
- 调试与测试记录使用项目模板。

### 回退上游阶段的情况

- 需求或验收标准不合理时回到阶段 1；
- 器件能力或采购替代问题回到阶段 2；
- 电路连接或参数问题回到阶段 3，并重新执行阶段 4；
- 布局、热、机械或规则问题回到阶段 5；
- 布线、回流或铺铜问题回到阶段 6；
- 制造输出或装配问题回到阶段 7。

## 12. 项目完成后的维护任务

简历整理、项目展示、仓库导航优化和经验复盘不作为顶层硬件阶段。只有在测试和实际职责有可追溯证据时，才能提炼 README 或简历描述；不得把未完成、未制造或未验证内容写成实际成果。

## 13. 流程使用规则

需要读取本文的场景：

- 判断完整八阶段流程或当前阶段；
- 判断阶段进入、退出或回退条件；
- 执行新项目初始化；
- 维护流程、结构标准或模板；
- 跨阶段审查或制造放行。

普通 datasheet 阅读、单次器件选型、单次原理图审查、PCB 审查、调试记录或小幅 README 维护，不默认读取本文；应按 `docs/AI_Context_Guide.md` 读取当前项目、当前阶段 Skill、checklist 和被修改文件。
