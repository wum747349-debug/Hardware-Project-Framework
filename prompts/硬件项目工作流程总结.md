# 硬件项目工作流程总结

## 1. 文档定位

本文档是给用户查看和复盘用的硬件项目流程说明，用于帮助理解一个低压嵌入式硬件项目应该如何从需求定义逐步推进到原理图、PCB、打样、调试、测试和总结。

本文件不是 AI 普通任务的默认读取上下文。AI 执行具体任务时，应优先遵循 `docs/AI_Context_Guide.md`，只读取当前项目、当前阶段 Skill 和必要仓库规则。

本文较长，给 AI/Codex/Claude 布置任务时不要全文粘贴，只复制当前阶段或当前问题相关片段。本文可以作为用户学习、阶段复盘和任务布置参考，但不替代仓库执行规则。

与 `docs/08_Project_Workflow.md` 的关系：

- `docs/08_Project_Workflow.md` 是仓库内的标准执行流程，偏向给 AI 和仓库维护任务提供统一规则。

- 本文档是面向用户的复盘版说明，偏向解释“现在处于哪个阶段、下一步该做什么、阶段成果是否完整”。

- 如果两者出现细节差异，以 `docs/08_Project_Workflow.md` 和 `docs/AI_Context_Guide.md` 作为仓库执行依据；本文档用于阅读、复盘和布置任务时快速引用。

推荐使用方式：

- 新项目开始前，用本文档了解整体流程。

- 某个阶段不知道下一步做什么时，查对应阶段说明。

- 项目完成后，用本文档检查是否漏掉设计记录、审查记录、测试记录或改版记录。

- 给 Codex / Claude 布置任务时，只引用当前阶段或当前问题相关内容，不要求 AI 每次读取全文。

## 3. 20 个阶段总览

一个硬件项目建议按以下顺序推进：

```text
1. 需求定义
2. 系统框图
3. 第一轮关键器件识别与候选
4. 按需资料收集与 Datasheet 阅读
5. 器件选型与模块设计决策
6. BOM 草稿
7. 原理图设计准备
8. 原理图绘制
9. 原理图审查
10. PCB Layout 前规划
11. PCB Layout
12. PCB 审查
13. 制造文件输出
14. 打样
15. 焊接
16. 上电调试
17. 功能测试
18. 测试报告
19. 改版记录
20. 项目总结与简历整理
```

核心原则：

- 需求不清楚时，不要急着选型。

- 第一轮不是把所有元器件资料全部下载完，而是先识别影响架构和关键电路参数的器件。

- 选型没有依据时，不要急着画原理图。

- 原理图没有审查时，不要急着 PCB Layout。

- PCB 没有审查时，不要急着打样。

- 打样前必须确认制造文件完整。

- 首次上电必须使用限流电源。

- 每个关键参数都要能追溯到 datasheet、reference manual 或 application note。

- 每个阶段都要留下文档记录，方便复盘和改版。

## 阶段 1：需求定义

目标：明确项目要做什么、不做什么、第一版边界是什么。

需要更新：

```text
projects/项目名/README.md
projects/项目名/requirements.md
```

需要明确：

- 项目目标。

- 输入电源范围。

- 输出电源和预计电流。

- MCU 或主控需求。

- 通信接口需求。

- ADC / DAC / 传感器需求。

- 执行控制输出需求。

- 按键、LED、人机交互需求。

- 调试接口需求。

- 测试点要求。

- PCB 层数、尺寸和手焊约束。

- 第一版明确不做的功能。


阶段通过标准：

- 需求已经能支撑器件选型和原理图设计。

- 关键参数没有明显空白。

- 第一版边界清楚，不追求过度复杂。


---

## 阶段 2：系统框图

目标：把项目拆成清晰的功能模块，明确电源流向和信号流向。

需要更新：

```text
projects/项目名/block_diagram.md
```

推荐框图结构：

```text
输入电源
  ↓
保护 / 滤波
  ↓
稳压电源
  ↓
主控 MCU
  ├─ 调试接口
  ├─ 通信接口
  ├─ 采集输入
  ├─ 控制输出
  ├─ 人机交互
  └─ 测试点
```

阶段通过标准：

- 模块边界清楚。

- 电源路径清楚。

- 主要信号路径清楚。

- 后续可以按模块进行资料收集和选型。


---

## 阶段 3：第一轮关键器件识别与候选

目标：在需求和模块边界明确后，先找出影响架构、供电、安全、接口和关键电路参数的器件类别，并形成搜索关键词、筛选条件和候选表。

需要更新：

```text
projects/项目名/references.md
projects/项目名/design_notes.md
```

第一轮不是把所有元器件资料全部下载完。第一轮重点通常包括：

- MCU。

- 主电源芯片。

- 关键接口芯片。

- 关键连接器。

- 关键时钟器件。

- 功率开关器件，例如 MOSFET。

- 关键模拟 / 保护器件，例如运放、ADC、参考电压、ESD/TVS、保险或保护芯片。

普通电阻、电容、LED、普通排针、测试点、普通按键、跳帽等外围器件后置，等模块电路参数明确后再选。

立创商城主要由用户手动搜索、筛选、检查库存/价格/封装/基础库状态和下载资料。AI/Codex 负责整理：

- 搜索关键词。

- 筛选条件。

- 候选表字段。

- 参数比较维度。

- 风险点。

- 待核对项。

资料收集从这一阶段开始，但不是一次性完成；只围绕当前模块和当前候选器件按需下载 datasheet / reference manual / application note。

开源项目使用原则：

- 只参考结构、模块划分、接口组织、文档组织和制造输出组织方式。

- 不能直接复制原理图、PCB、BOM、Gerber、生产文件或源工程文件。

- 关键参数必须回到 datasheet、reference manual 或 application note 核对。


阶段通过标准：

- 第一轮关键器件类别已经列出。

- 每类关键器件已有搜索关键词、筛选条件和 2-3 个候选方向。

- 普通外围器件已明确后置。

- 需要下一步阅读的 datasheet / reference manual / application note 已记录到 `references.md`。


---

## 阶段 4：按需资料收集与 Datasheet 阅读

目标：围绕当前模块和当前设计决策，从 datasheet / reference manual / application note 中提取可以支撑设计的关键参数。

对应 Skill：

```text
skills/hardware-datasheet-reading/SKILL.md
```

需要更新：

```text
projects/项目名/references.md
projects/项目名/design_notes.md
```

需要提取：

- 器件型号、厂商、功能定位和封装。

- 推荐工作条件。

- 绝对最大额定值。

- 引脚功能。

- 典型应用电路。

- 外围器件推荐值。

- 输入输出电容要求。

- ADC 输入范围。

- MOSFET 驱动条件。

- 运放输入输出范围。

- 参考电压要求。

- PCB Layout 注意事项。

- 风险项和待确认项。


注意：

- 不要把 Absolute Maximum Ratings 当作正常工作条件。

- 不要直接照抄典型应用电路。

- 不要在没有 datasheet 依据时确认关键参数。

- 不要要求用户一次性下载全部器件资料；只读取当前模块和当前候选所需资料。

- 立创商城商品页只能作为 C 编号、库存、价格、封装和资料入口参考，不能替代 datasheet。


阶段通过标准：

- 关键器件参数已经足够支撑选型。

- 不确定项已经明确记录。


---

## 阶段 5：器件选型与模块设计决策

目标：确定第一版硬件的主选器件和替代器件。

对应 Skill：

```text
skills/hardware-component-selection/SKILL.md
```

需要更新：

```text
projects/项目名/design_notes.md
projects/项目名/references.md
BOM 草稿
```

选型原则：

- 常见、易采购、资料完整。

- 官方资料清晰。

- 有典型应用电路。

- 有替代料。

- 封装适合手焊或普通 PCB 打样。

- Altium 符号和封装容易建立或检查。

- 不追求过度复杂。

- 便于测试和调试。


关键器件类别：

- MCU。

- 电源芯片。

- USB-C 连接器。

- 保护器件。

- MOSFET。

- 运放。

- ADC。

- 参考电压。

- 接插件。

后置外围器件：

- 普通电阻、电容。

- LED、普通按键。

- 普通排针、测试点、跳帽。

- 不影响模块架构的通用小器件。

这些外围器件应在关键器件 datasheet、模块电路参数和封装工艺要求明确后再补充，不作为第一轮重点资料收集对象。


阶段通过标准：

- 关键器件已有主选型号、替代型号、封装和风险说明。

- 关键参数有 datasheet 依据。

- 第一版 BOM 草稿可以支撑原理图绘制。


---

## 阶段 6：BOM 草稿

目标：把器件选型结果整理成后续原理图、采购和替代料检查都能使用的清单。

需要更新：

```text
BOM 草稿
projects/项目名/design_notes.md
projects/项目名/references.md
```

BOM 草稿建议记录：

- 器件类别。

- 主选型号。

- 替代型号。

- 封装。

- 关键参数来源。

- 采购状态。

- 是否适合手焊或当前 PCB 工艺。

- 风险点。

- datasheet 待核对项。


注意：

- 不要直接照抄开源项目 BOM。

- 不要把未核对的典型值当作最终设计结论。

- 对电源、锂电池、MOSFET、ADC 输入、运放和参考电压相关器件，需要保留 datasheet 核对入口。


阶段通过标准：

- 关键器件已经有主选和备选记录。

- 每个关键器件都能追溯到资料来源。

- BOM 草稿可以支撑原理图绘制和后续采购检查。


---

## 阶段 7：原理图设计准备

目标：在打开 Altium 画图前，先规划模块、页面、网络名和测试点。

需要更新：

```text
projects/项目名/design_notes.md
```

建议规划：

- 原理图页面结构。

- 模块划分。

- 电源网络命名。

- 信号网络命名。

- 接口命名。

- 测试点命名。

- 关键器件放置逻辑。

- 原理图注释策略。


常见模块：

```text
1. 电源输入
2. 输入保护
3. 稳压电源
4. MCU 最小系统
5. 调试接口
6. 通信接口
7. 模拟输入
8. 驱动输出
9. 按键
10. LED
11. 测试点
```

阶段通过标准：

- 每个模块的功能、器件、连接关系和测试点已经明确。

- 可以开始在 Altium Designer 中绘制原理图。

## 阶段 8：原理图绘制

目标：在 Altium Designer 中完成第一版原理图。

需要维护：

```text
projects/项目名/hardware/altium_project/
projects/项目名/design_notes.md
```

推荐绘制顺序：

```text
1. 电源输入
2. 稳压电源
3. MCU 最小系统
4. SWD 调试接口
5. UART / I2C / SPI
6. ADC 输入
7. MOSFET 输出
8. LED 和按键
9. 测试点
10. 标题栏、版本、注释
```

每个模块完成后，应同步记录：

- 为什么这样连接。

- 参数依据。

- datasheet 待核对项。

- 风险点。

- 测试点设计。


阶段通过标准：

- 原理图已经完成。

- 已导出 PDF 或清晰截图。

- 可以进入原理图审查。


---

## 阶段 9：原理图审查

目标：在进入 PCB Layout 前发现高风险问题。

对应 Skill：

```text
skills/hardware-schematic-review/SKILL.md
```

需要更新：

```text
projects/项目名/docs/schematic_review.md
projects/项目名/design_notes.md
```

审查重点：

- 电源输入是否安全。

- USB-C CC 电阻是否正确。

- LDO / DC-DC 外围是否符合 datasheet。

- MCU VDD / VDDA / VSS / VSSA 是否完整。

- 去耦电容是否完整。

- NRST 是否合理。

- BOOT 配置是否合理。

- SWD 是否完整。

- UART / I2C / SPI 方向和电平是否正确。

- ADC 输入是否有限流、滤波和保护。

- MOSFET 是否能被 MCU GPIO 驱动。

- 感性负载是否有续流路径。

- 测试点是否足够。

- 封装和采购型号是否一致。


审查结论三选一：

```text
1. 可以进入 PCB Layout
2. 修改后再进入 PCB Layout
3. 存在高风险，暂不建议进入 PCB Layout
```

阶段通过标准：

- 高风险项已经解决。

- 或者高风险项已经明确标注为可接受待验证项。

- 可以进入 PCB Layout。


---

## 阶段 10：PCB Layout 前规划

目标：先规划布局，再正式布线。

需要更新：

```text
projects/项目名/design_notes.md
```

需要规划：

- 板子尺寸。

- 接口位置。

- 电源路径。

- MCU 位置。

- 调试接口位置。

- ADC 输入区域。

- MOSFET 输出区域。

- 敏感信号和噪声源隔离。

- 测试点可达性。

- 安装孔。

- 丝印。

- 地平面和回流路径。


阶段通过标准：

- 布局分区清楚。

- 关键走线路径清楚。

- 可以开始 PCB Layout。


---

## 阶段 11：PCB Layout

目标：完成 PCB 布局布线。

需要维护：

```text
projects/项目名/hardware/altium_project/
projects/项目名/design_notes.md
```

布局布线重点：

- 去耦电容靠近芯片电源脚。

- 电源路径短且足够宽。

- 地回流路径连续。

- ADC 输入远离 MOSFET 开关噪声。

- MOSFET 大电流路径加宽。

- SWD 接口方便连接。

- 测试点方便万用表和示波器探测。

- 丝印清晰。

- 接插件方向不容易接错。

- 预留安装孔。

- 满足板厂工艺能力。


阶段通过标准：

- PCB 完成。

- 初步 DRC 通过或问题已记录。

- 可以进入 PCB 审查。


---

## 阶段 12：PCB 审查

目标：在打样前发现布局、布线、可制造性和可调试性问题。

需要更新：

```text
projects/项目名/docs/pcb_review.md
```

审查重点：

- DRC 问题。

- 线宽线距。

- 电源线宽。

- 过孔。

- 地回流。

- 去耦电容位置。

- 接插件方向。

- 测试点。

## 单节锂电池充电与保护板推荐切入重点

当前项目：

```text
projects/02_LiIon_Charger_Protection_Board
```

推荐优先切入：

```text
1. 先明确电池类型、使用场景、输入接口、输出接口和第一版安全边界
2. 识别第一轮关键器件：充电芯片、保护芯片、关键连接器、保险/保护器件和电池相关器件
3. 提取充电管理、保护阈值、热设计、输入输出电容和 PCB Layout 注意事项
4. 确定充电管理、保护、状态指示、测试点和连接器的模块划分
5. 建立 BOM 草稿，并为充电芯片、保护芯片、MOSFET、连接器和保护器件保留替代料
6. 画原理图前先完成安全检查项：极性、防反接、短路、过流、过温、测试点和限流上电流程
7. 原理图审查时重点检查电池路径、充电路径、保护路径、热风险、封装和测试可达性
8. PCB Layout 前重点规划电流路径、散热铜皮、连接器方向、测试点和高风险网络间距
9. 首次上电和充电测试必须使用限流电源，并保持有人看管
10. 测试报告中记录输入条件、电池状态、输出状态、芯片温升、异常保护和未验证项
```

注意：

- 不在没有 datasheet 依据时确定充电电流、保护阈值、MOSFET 参数或热设计结论。

- 锂电池相关测试优先保守推进，安全规则高于进度。

## STM32 + 运放 + ADC 模拟采集板推荐切入重点

当前项目：

```text
projects/03_STM32_OpAmp_ADC_Acquisition_Board
```

推荐优先切入：

```text
1. 先明确输入信号类型、输入范围、采样目标、精度目标、供电方式和第一版边界
2. 识别第一轮关键器件：STM32、运放、外置 ADC、参考电压、输入保护和关键连接器
3. 提取运放供电范围、输入共模范围、输出摆幅、ADC 输入范围、参考电压要求和接口时序
4. 先规划模拟前端、参考电压、ADC、MCU、数字接口、输入保护和测试点模块
5. 建立 BOM 草稿，并为运放、ADC、参考电压、保护器件和关键无源器件保留替代料
6. 原理图设计前重点确认信号链：输入保护、限流、滤波、缓冲/放大、ADC 输入和参考电压
7. 原理图审查时重点检查运放供电余量、输入输出范围、ADC 参考、模拟地回流和接口电平
8. PCB Layout 前重点规划模拟区域、数字区域、参考电压区域、ADC 输入走线和噪声源隔离
9. 上电调试先验证电源、参考电压和空载 ADC 读数，再逐步引入输入信号

```

注意：

- 不在没有 datasheet 依据时确定运放输入输出范围、ADC 满量程、参考电压精度或抗混叠参数。

- 模拟采集项目要把“可测、可校准、可追溯”作为第一版优先级。

## 最重要的习惯

- 每次只推进一个项目。

- 每次只推进一个阶段。

- 每个阶段都要留下记录。

- 每个关键设计都要能说出依据。

- 每个问题都要记录原因和结果。

- 不急着画图，不急着打样，不跳过审查。

- 让项目形成完整闭环，而不是只保留 Altium 工程文件。
