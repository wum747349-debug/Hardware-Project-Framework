# 硬件项目工作流程总结

## 1. 文档定位

本文档是给用户查看和复盘用的硬件项目流程说明，用于帮助理解一个低压嵌入式硬件项目应该如何从需求定义逐步推进到原理图、PCB、打样、调试、测试和总结。

本文件不是 AI 普通任务的默认读取上下文。AI 执行具体任务时，应优先遵循 `docs/AI_Context_Guide.md`，只读取当前项目、当前阶段 Skill 和必要仓库规则。

推荐使用方式：

- 新项目开始前，用本文档了解整体流程。
    
- 某个阶段不知道下一步做什么时，查对应阶段说明。
    
- 项目完成后，用本文档检查是否漏掉设计记录、审查记录、测试记录或改版记录。
    
- 给 Codex / Claude 布置任务时，只引用当前阶段相关内容，不要求 AI 每次读取全文。
    

---

## 2. 总体流程

一个硬件项目建议按以下顺序推进：

```text
1. 需求定义
2. 系统框图
3. 官方资料收集
4. Datasheet 阅读与关键参数提取
5. 器件选型
6. BOM 草稿
7. 原理图设计准备
8. 原理图绘制
9. 原理图审查
10. PCB Layout 前规划
11. PCB Layout
12. PCB 审查
13. 制造文件输出
14. 打样
15. 焊接
16. 上电调试
17. 功能测试
18. 测试报告
19. 改版记录
20. 项目总结与简历整理
```

核心原则：

- 需求不清楚时，不要急着选型。
    
- 选型没有依据时，不要急着画原理图。
    
- 原理图没有审查时，不要急着 PCB Layout。
    
- PCB 没有审查时，不要急着打样。
    
- 打样前必须确认制造文件完整。
    
- 首次上电必须使用限流电源。
    
- 每个关键参数都要能追溯到 datasheet、reference manual 或 application note。
    
- 每个阶段都要留下文档记录，方便复盘和改版。

## 3. 阶段 1：需求定义

目标：明确项目要做什么、不做什么、第一版边界是什么。

需要更新：

```text
projects/项目名/README.md
projects/项目名/requirements.md
```

需要明确：

- 项目目标。
    
- 输入电源范围。
    
- 输出电源和预计电流。
    
- MCU 或主控需求。
    
- 通信接口需求。
    
- ADC / DAC / 传感器需求。
    
- 执行控制输出需求。
    
- 按键、LED、人机交互需求。
    
- 调试接口需求。
    
- 测试点要求。
    
- PCB 层数、尺寸和手焊约束。
    
- 第一版明确不做的功能。
    

阶段通过标准：

- 需求已经能支撑器件选型和原理图设计。
    
- 关键参数没有明显空白。
    
- 第一版边界清楚，不追求过度复杂。

## 4. 阶段 2：系统框图

目标：把项目拆成清晰的功能模块，明确电源流向和信号流向。

需要更新：

```text
projects/项目名/block_diagram.md
```

推荐框图结构：

```text
输入电源
  ↓
保护 / 滤波
  ↓
稳压电源
  ↓
主控 MCU
  ├─ 调试接口
  ├─ 通信接口
  ├─ 采集输入
  ├─ 控制输出
  ├─ 人机交互
  └─ 测试点
```

阶段通过标准：

- 模块边界清楚。
    
- 电源路径清楚。
    
- 主要信号路径清楚。
    
- 后续可以按模块进行资料收集和选型。
    

---

## 5. 阶段 3：官方资料收集

目标：建立项目的资料依据，不依赖教程、博客或开源项目直接定关键参数。

需要更新：

```text
projects/项目名/references.md
```

需要收集：

- MCU datasheet。
    
- MCU reference manual。
    
- 官方硬件设计 application note。
    
- 电源芯片 datasheet。
    
- USB-C 供电相关资料。
    
- MOSFET datasheet。
    
- 运放 datasheet。
    
- ADC datasheet。
    
- 参考电压 datasheet。
    
- ESD / TVS / 保护器件 datasheet。
    
- 连接器 datasheet。
    
- 官方评估板原理图。
    
- 必要的开源项目参考链接。
    

开源项目使用原则：

- 只参考结构、模块划分、接口组织、文档组织和制造输出组织方式。
    
- 不能直接复制原理图、PCB、BOM、Gerber、生产文件或源工程文件。
    
- 关键参数必须回到 datasheet、reference manual 或 application note 核对。
    

阶段通过标准：

- 关键器件已经有官方资料来源。
    
- `references.md` 已记录资料来源、参考用途和待提取内容。

## 6. 阶段 4：Datasheet 阅读与关键参数提取

目标：从官方资料中提取可以支撑设计的关键参数。

对应 Skill：

```text
skills/hardware-datasheet-reading/SKILL.md
```

需要更新：

```text
projects/项目名/references.md
projects/项目名/design_notes.md
```

需要提取：

- 器件型号、厂商、功能定位和封装。
    
- 推荐工作条件。
    
- 绝对最大额定值。
    
- 引脚功能。
    
- 典型应用电路。
    
- 外围器件推荐值。
    
- 输入输出电容要求。
    
- ADC 输入范围。
    
- MOSFET 驱动条件。
    
- 运放输入输出范围。
    
- 参考电压要求。
    
- PCB Layout 注意事项。
    
- 风险项和待确认项。
    

注意：

- 不要把 Absolute Maximum Ratings 当作正常工作条件。
    
- 不要直接照抄典型应用电路。
    
- 不要在没有 datasheet 依据时确认关键参数。
    

阶段通过标准：

- 关键器件参数已经足够支撑选型。
    
- 不确定项已经明确记录。

## 7. 阶段 5：器件选型

目标：确定第一版硬件的主选器件和替代器件。

对应 Skill：

```text
skills/hardware-component-selection/SKILL.md
```

需要更新：

```text
projects/项目名/design_notes.md
projects/项目名/references.md
BOM 草稿
```

选型原则：

- 常见、易采购、资料完整。
    
- 官方资料清晰。
    
- 有典型应用电路。
    
- 有替代料。
    
- 封装适合手焊或普通 PCB 打样。
    
- Altium 符号和封装容易建立或检查。
    
- 不追求过度复杂。
    
- 便于测试和调试。
    

关键器件类别：

- MCU。
    
- 电源芯片。
    
- USB-C 连接器。
    
- 保护器件。
    
- MOSFET。
    
- 运放。
    
- ADC。
    
- 参考电压。
    
- 接插件。
    
- 测试点。
    
- LED、按键、电阻、电容。
    

阶段通过标准：

- 关键器件已有主选型号、替代型号、封装和风险说明。
    
- 关键参数有 datasheet 依据。
    
- 第一版 BOM 草稿可以支撑原理图绘制。

```text

6. 通信接口
7. 模拟输入
8. 驱动输出
9. 按键
10. LED
11. 测试点
```

阶段通过标准：

- 每个模块的功能、器件、连接关系和测试点已经明确。

## 9. 阶段 7：原理图绘制

目标：在 Altium Designer 中完成第一版原理图。

需要维护：

```text
projects/项目名/hardware/altium_project/

```

推荐绘制顺序：

```text
1. 电源输入
2. 稳压电源
3. MCU 最小系统
4. SWD 调试接口
5. UART / I2C / SPI

7. MOSFET 输出
8. LED 和按键
9. 测试点

```

每个模块完成后，应同步记录：

- 为什么这样连接。
    
- 参数依据。
    
- datasheet 待核对项。
    
- 风险点。
    
- 测试点设计。
    

阶段通过标准：

- 原理图已经完成。
    
- 已导出 PDF 或清晰截图。
    
- 可以进入原理图审查。

## 10. 阶段 8：原理图审查

目标：在进入 PCB Layout 前发现高风险问题。

对应 Skill：

```text
skills/hardware-schematic-review/SKILL.md
```

需要更新：

```text
projects/项目名/docs/schematic_review.md
projects/项目名/design_notes.md
```

审查重点：

- 电源输入是否安全。
    
- USB-C CC 电阻是否正确。
    
- LDO / DC-DC 外围是否符合 datasheet。
    
- MCU VDD / VDDA / VSS / VSSA 是否完整。
    
- 去耦电容是否完整。
    
- NRST 是否合理。
    
- BOOT 配置是否合理。
    
- SWD 是否完整。
    
- UART / I2C / SPI 方向和电平是否正确。
    
- ADC 输入是否有限流、滤波和保护。
    
- MOSFET 是否能被 MCU GPIO 驱动。
    
- 感性负载是否有续流路径。
    
- 测试点是否足够。
    
- 封装和采购型号是否一致。
    

审查结论三选一：

```text
1. 可以进入 PCB Layout
2. 修改后再进入 PCB Layout
3. 存在高风险，暂不建议进入 PCB Layout
```

阶段通过标准：

- 高风险项已经解决。
    
- 或者高风险项已经明确标注为可接受待验证项。
    
- 可以进入 PCB Layout。

需要更新：

```text

```

- 电源路径。

- ADC 输入区域。

## 12. 阶段 10：PCB Layout

目标：完成 PCB 布局布线。

需要维护：

```text
projects/项目名/hardware/altium_project/
projects/项目名/design_notes.md
```

布局布线重点：

- 去耦电容靠近芯片电源脚。
    
- 电源路径短且足够宽。
    
- 地回流路径连续。
    
- ADC 输入远离 MOSFET 开关噪声。
    
- MOSFET 大电流路径加宽。
    
- SWD 接口方便连接。
    
- 测试点方便万用表和示波器探测。
    
- 丝印清晰。
    
- 接插件方向不容易接错。
    
- 预留安装孔。
    
- 满足板厂工艺能力。
    

阶段通过标准：

- PCB 完成。
    
- 初步 DRC 通过或问题已记录。
    
- 可以进入 PCB 审查。

## 13. 阶段 11：PCB 审查

目标：在打样前发现布局、布线、可制造性和可调试性问题。

需要更新：

```text
projects/项目名/docs/pcb_review.md
```

审查重点：

- DRC 问题。
    
- 线宽线距。
    
- 电源线宽。
    
- 过孔。
    
- 地回流。
    
- 去耦电容位置。
    
- 接插件方向。
    
- 测试点。
    
- 丝印。
    
- 板边距离。
    
- 安装孔。
    
- 可焊接性。
    
- 可调试性。
    
- Gerber 输出风险。
    

审查结论三选一：

```text
1. 可以输出制造文件
2. 修改后再输出制造文件
3. 存在高风险，暂不建议打样
```

## 16. 阶段 14：焊接

目标：按风险顺序焊接，降低一次性全焊导致难排查的问题。

建议顺序：

```text
1. 电源入口
2. 保护器件
3. 稳压电源
4. MCU 最小系统
5. SWD 调试接口
6. LED / 按键
7. 通信接口
8. ADC 输入
9. MOSFET 输出
```

焊接后检查：

- 极性。
    
- 短路。
    
- 虚焊。
    
- 连锡。
    
- 阻值。
    
- 电源与 GND 是否短路。
    
- 芯片方向。
    
- 接插件方向。

## 17. 阶段 15：上电调试

目标：安全验证硬件是否能上电和下载程序。

需要更新：

```text
projects/项目名/docs/bringup_log.md
```

首次上电必须：

- 使用限流电源。
    
- 先检查短路。
    
- 先测输入电压。
    
- 再测关键电源轨。
    
- 观察静态电流。
    
- 确认无异常发热。
    

调试顺序：

```text
1. 外观检查
2. 电源短路检查
3. 限流上电
4. 关键电源轨测量
5. MCU 供电测量
6. NRST / BOOT 检查
7. SWD 下载
8. LED 测试
9. 按键测试
10. UART 测试
11. I2C / SPI 测试
12. ADC 输入测试
13. MOSFET 输出测试
```

异常记录格式：

```text
问题编号：
现象：
测试条件：
可能原因：
排查步骤：
结果：
解决方案：
是否需要改版：
```

## 21. 第一版 STM32 数据采集/控制开发板推荐推进顺序

当前项目：

```text
projects/01_STM32_DAQ_Control_Board
```

推荐推进顺序：

```text
1. 细化 requirements.md
2. 完善 block_diagram.md
3. 确定 MCU 主选型号
4. 收集 STM32 官方资料
5. 提取 STM32 datasheet / reference manual 关键参数
6. 确定 USB-C 供电方案
7. 确定 3.3V 稳压方案
```

## 25. 最重要的习惯

- 每次只推进一个项目。
    
- 每次只推进一个阶段。
    
- 每个阶段都要留下记录。
    
- 每个关键设计都要能说出依据。
    
- 每个问题都要记录原因和结果。
    
- 不急着画图，不急着打样，不跳过审查。
    
- 让项目形成完整闭环，而不是只保留 Altium 工程文件。
